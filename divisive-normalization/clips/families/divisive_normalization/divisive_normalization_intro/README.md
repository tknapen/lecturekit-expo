# divisive_normalization_intro

Not for a slide yet. This clip is manim8's `divisive_normalization` example, copied into the expo as the first
end-to-end test of the seam between manim8 and lecturekit: the workspace, the family environment at a pinned manim8
commit, the bridged style, `lk clips`, the index and the continuous build. It is on no slide of this deck, and it
must not be put on one as it stands.

## Why it cannot go on a slide

The clip draws `r = E / (sigma + P)`. That equation is a schematic: the example stores it as such
(`equations: schematic_equation`, its symbols are "schematic response" and so on), the clip labels its curve
"schematic curve from the equation", and manim8's example says plainly that it is "not offered as a full or generally
correct biophysical normalization model". The data in `data/synthetic_responses.csv` are synthetic toy values that
satisfy that equation with `sigma = 1`, labelled "synthetic data" in the clip; they are not measurements.

The lecture this project is for is built on Carandini and Heeger 2012 and Aqil, Knapen and Dumoulin 2021 (see
`sources/` of the deck). Before this clip, or one grown from it, goes on a slide:

1. the equation is replaced by the form the lecture states, taken from those sources (with its exponents, the
   semisaturation constant and the pool as the source defines them), and `FACTS.md` records where it comes from;
2. the synthetic data are replaced by values from the deck's own simulation in `sims/`, or the plot that shows them
   is removed;
3. the lecturer signs the change off (the equation is a claim of the lecture, which the lecturer decides), and the
   deck's `README.md` log says so.

Until then, `lk clips` renders it in the continuous build so that the seam stays tested, and the committed
`assets/clips/divisive_normalization_intro.mp4`, its checkpoint stills and the `clips.json` entry are the fallback
of that test, not material of the lecture.

## What it is

- Copied with `scianim project init divisive_normalization_intro --family divisive_normalization --from-example
  divisive_normalization` from manim8 0.1.0a0 (commit 4a39c34), so the id is this directory's name.
- Two scenes, 18 s: `excitation` (0 to 6 s, the drive curve from the synthetic data, a gain sweep) and
  `normalization` (6 to 18 s, the schematic curve beside the equation; the pool P rises to 4, then sigma rises to 3
  while P falls back to 1).
- Checkpoints: `excitation_visible` (4 s), `pool_introduced` (8 s), `pool_raised` (13 s) and `rebalanced` (17.2 s).
  The still `lk clips` copies into the index is `rebalanced`, the latest, unless
  `lk clips --still divisive_normalization_intro=<id>` names another.
- Changed from the example, each through a manim8 proposal recorded in `proposals/applied/`: the output is 1280 by
  720 at 30 fps (the example renders 1920 by 1080), and the style is the deck's bridged `lecturekit_paper@0.1.0`
  (`lk theme divisive-normalization --manim8 0.1.0`), in place of `tomas_scientific`.
- `code/` is generated by `scianim codegen`, which `lk clips` runs before each render; it is committed for
  review, as manim8's workspaces do, and never edited by hand.

## Rendering it

```sh
lk clips divisive-normalization            # syncs the family environment once, renders, copies into assets/clips
python tools/check_clips.py divisive-normalization   # the index against the manifest of the job
```

The family environment (`../pyproject.toml`, `../uv.lock`) takes manim8's bridge and contracts from GitHub at the
commit the control plane was installed from (4a39c34, the `v0.1.0a0` tag that lecturekit 0.3.0's manim8 extra
names). Moving manim8: install the lecturekit that names the new tag, set `rev` of both sources in
`../pyproject.toml` to the new commit, run `uv lock` in `..`, and render again.
